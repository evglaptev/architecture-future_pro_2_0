## Task3Advanced Overview

| Артефакт | Назначение |
| --- | --- |
| `c4-container.puml` | Контейнерный уровень целевой архитектуры Future 2.0 |
| `c4-component.puml` | Компонентная модель портала самообслуживания данных |
| `risk-map.md` | Матрица рисков трансформации (вероятность/влияние) с индикаторами |
| `risk-management-plan.md` | План управления рисками с мерами и ответственными |

### Ключевые акценты

- Разделение доменов (медицина, финтех, AI, партнёры) и единый событийный контур Kafka + Flink.
- Data Mesh платформа и self-service BI снимают нагрузку с SQL Server; легаси DWH используется как временный мост.
- Портал включает компоненты авторизации, оркестрации запросов, каталога, конструктора отчётов и audit-ядра.
- Риски покрывают технические, организационные и финансовые аспекты, для каждого определены конкретные действия.

## Миграция логики ESB (Apache Camel)

В целевой архитектуре Apache Camel сохраняется только как **«мост совместимости»** к легаси DWH. Остальные функции ESB перераспределены:

| Функция ESB | Новый компонент |
| --- | --- |
| Маршрутизация на основе контента | Kafka (топики по доменам + Streams) + API Gateway (для синхронных запросов) |
| Трансформация сообщений | Flink (потоки) / dbt (batch) / антикоррупционные слои доменов |
| Валидация, проверка ФЛК | Flink + Schema Registry (Avro) + валидация в API Gateway |
| Оркестрация процессов (саги) | Доменные события + координаторы на Go/Java (подписчики Kafka) |
| Управление очередями и dead letter | Kafka native DLQ + Flink для мониторинга и репроцессинга |
| Синхронный request‑reply | Прямые gRPC/REST через API Gateway (без промежуточной шины) |

**Batch-данные** (от партнёров, исторические загрузки) принимаются через Airflow/Dagster в Data Mesh напрямую, минуя Kafka.
