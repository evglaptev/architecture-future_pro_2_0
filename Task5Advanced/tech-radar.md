## Расширенный техрадар

| Технология / паттерн | Область применения | Статус | Обоснование |
| --- | --- | --- | --- |
| Data Mesh + Domain Data Products | Организация данных по доменам | **Adopt** | Уже стартовали доменные команды, паттерн решает узкое горлышко DWH и описан в дорожной карте |
| Event-driven Architecture (Kafka + Schema Registry) | Интеграции и аналитика near real-time | **Adopt** | События становятся единым контрактом, поддержаны Flink и self-service BI; **заменяет старый SOA + ESB подход** |
| Lakehouse (Delta Lake + dbt Core) | Хранение и трансформации данных | **Adopt** | Позволяет совмещать batch/stream, поддерживает версионность и time-travel |
| Self-service BI Portal (React + GraphQL + Trino) | Портал аналитиков | **Trial** | MVP реализуется в течение года, требуется обратная связь пользователей |
| Feature Store (Feast / Vertex Feature Store) | Повторное использование ML-фич | **Trial** | Нужен для AI сервисов, но пока покрывает только часть моделей |
| Data Contracts / AsyncAPI | Управление схемами событий | **Trial** | Схемы версионируются и проверяются автоматикой, внедряются вместе с Kafka |
| Service Mesh (Istio/Linkerd) | Безопасность между доменами | **Assess** | Рассматривается для zero-trust между доменами и партнёрами |
| Reverse ETL | Отправка аналитики обратно в продукты | **Assess** | Возможно после стабилизации Data Mesh, чтобы персонализировать фронты |
| **SOA + ESB (Apache Camel)** | Интеграционная шина, синхронные маршруты | **Hold** | **Архитектурный подход SOA с централизованной ESB заменяется на EDA с брокером событий (Kafka) и Data Mesh.** Camel используется только как временный мост совместимости к легаси DWH, выводится из эксплуатации к 36 месяцу |
| PowerBuilder UI / Power BI отчёты с прямым доступом к DWH | Наследованный UI и отчёты | **Hold** | Новые сценарии запрещены, системы планомерно отключаются после запуска портала |
